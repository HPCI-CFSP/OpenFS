変数・単位 / Variables and units

F64, F32
標本の精度別FLOP数。FMAは元カウンタ処理で2演算。 / Precision-specific sampled FLOP counts; FMA is counted as two operations in the source parser.
D, d
HBM byte数、標本時間（ns→秒）。L2 bytesは表示するが式には使わない。 / HBM bytes and sampled duration (ns→s); L2 bytes are disclosed but not scaled.
P64, P32, B
1 GPUのvector TFLOP/s、HBM GB/s。十進単位:10¹² FLOP/s、10⁹ byte/s。 / Theoretical vector peaks and HBM bandwidth for one GPU, in decimal units.
T0, W, k
通常3反復のcompute中央値、別トレース窓、窓内カーネル時間。 / Median compute time of three normal runs, separate trace window, traced kernel duration.

計算順序 / Calculation

  1. カーネルごとに有効標本の変数別中央値。 / Component-wise medians of valid samples per kernel.
  2. R(P,B)=max(F64/(P64×10¹²)+F32/(P32×10¹²), D/(B×10⁹))。精度別compute時間を加算。正の仕事量のピーク不明なら算定不可。 / Sum typed compute times; missing peak for positive work makes the estimate unavailable.
  3. 元のR0、先のR1、標本時間d。R0≤d: q=(max(0,d−R0)+R1)/d。R0>d: q=max(1,R1/R0)。代替仮定 q_alt=R1/R0、R0=0なら1。 / Preserve residual where feasible; otherwise avoid spurious speedup. Alternate ratio retains efficiency.
  4. old=k×T0/W、予測 old×q。未計測カーネルはoldのまま。GPU時間和は排他的区間との一致が必要。 / Allocate normal time by trace ratio; hold uncovered kernels. Overlap requires another critical-path model.
  5. fixed=Σ(non-GPU trace parts)×T0/W。compute_prediction=Σ(old×q)+fixed。通常の全体時間中央値行のcompute/T0比を掛け、その行の初期化・終了処理を加える。 / Rescale to the representative normal phase row, then add initialization/finalization.
  6. q/q_altの最小最大と固定区間0.5–2倍で範囲を求める。統計的信頼区間ではない。 / Range combines both ratios with0.5–2× fixed-time sensitivity, not statistical confidence.

適用範囲 / Applicability

公開短時間例題のsource-only条件付き感度。AMD実測・CUDA→ROCm同等移植は未検証。正式EEA1、長時間精度、25%達成、調達判断の根拠ではありません。CPU、起動、同期、転送、キャッシュ、電力、実効クロック変化は未同定。未計測カーネル保持は仕事量ゼロの証明ではありません。

Source-only sensitivity for public short examples. AMD hardware and equivalent CUDA-to-ROCm ports are unvalidated. Not formal EEA1, long-run accuracy,25% success or procurement evidence. CPU, launch, synchronization, transfers, cache, power and effective clocks are unidentified. Holding uncovered kernels does not prove zero work.
