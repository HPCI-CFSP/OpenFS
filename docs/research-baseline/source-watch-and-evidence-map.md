# Source Watch Registry and Evidence Map

OpenFS separates pages that should be revisited from documents that support a
specific statement.

## Watch targets

`config/source-watch-registry.json` is the manually reviewed list of recurring
official indexes, release feeds, standards pages, committee pages, resource
registries, and document hubs. Each target names the affected canonical Topic
IDs, roadmap IDs, and Monitor IDs. Stable routing fields live in the registry;
timestamps, content digests, HTTP status, and change detections belong to the
Run-specific `source-watch-state.json` file.

A changed page is not evidence by itself. The Worker classifies the change,
ignores layout, advertising, ordering, and timestamp-only changes, and follows a
semantic change to an exact primary document. The resulting proposal still
requires independent validation and the applicable Consensus Gate.

## Evidence map

`knowledge/public/source-catalog-map.json` is generated by
`tools/build_source_catalog_map.py`. It deduplicates the exact URLs registered by
published roadmaps and topic decision-support records, then maps each URL to:

- every roadmap source ID and catalog source ID that registers it;
- the roadmap tracks that cite it;
- active canonical Topics, with either `direct-topic-evidence` or the broader
  `roadmap-family-context` mapping basis; and
- any recurring Watch target whose URL scope contains the evidence.

Source records that are not cited by a catalog item are listed explicitly in
`unmapped_catalog_source_ids`; the generator does not invent a Topic mapping.

Regenerate the map after changing a roadmap source, Topic decision-support
item, roadmap portfolio mapping, or Watch target:

```bash
python3 tools/build_source_catalog_map.py
```

Repository validation fails when the checked-in map is stale. AI agents should
use the Watch Registry to decide where to look and the Evidence Map to determine
which catalog and roadmap surfaces may be affected.

## Catalog and roadmap linkage

`config/roadmap-portfolio.json` is the many-to-many family-level mapping between
canonical Topics and roadmaps. Pages invert this mapping so that a catalog Topic
lists all relevant roadmaps and each published roadmap links back to all active
Topics. A published roadmap is linked to its detail page; a roadmap that has not
yet been published is marked as planned instead of receiving a broken link. The
Evidence Map adds source and track granularity without duplicating prose.
