# OFS-002: 過去FS資料からの調査ベースライン継承・更新

## 目的

FS1.0、FS2.0、FS3.0および今後のFS成果物から、HPCI整備計画で継続的に調査すべき項目を抽出し、`config/research-baseline.json`を根拠付きで更新する。

## 現在の整備状況

初期公開版は`docs/research-baseline/source-corpus.md`の4資料から作成した。2026-08-23に文部科学省の令和4～7年度ページで公開された26資料を登録・レビューし、初期30件の調査項目を保持したまま27件を追加した。FS1.0、各センターの現況を示す一次情報、評価基準の策定責任者と重み付け、および別のFS3提案書の公開区分は未確認である。

## 主な問い

- 過去FSの各調査項目は現在も継承すべきか、内容を改訂すべきか、複数項目へ分割すべきか、または終了条件を満たしたか。
- 過去FSの提言のうち、実装済み、未実装、前提変更、陳腐化、追加検証が必要なものは何か。
- アーキテクチャ、システムソフトウェア、アプリケーション、分野横断課題の間に抜けや重複はないか。
- 各項目を監視する情報源クラス、更新頻度、成果物、評価基準は何か。

## 処理手順

1. 資料の版、公開区分、取得元、SHA-256、原資料との関係を登録する。
2. 章・調査項目・提言を原子化し、既存`topic_id`との対応を作る。
3. 各項目を`inherited`、`revised`、`split`、`merged`、`candidate-retirement`、`new`のいずれかとして提案する。
4. 人またはAIが提案した追加項目について、複数の独立レビューと、人が発行した指示（Directive）を経て、ベースラインを変更するプルリクエストを作成する。
5. 変更後、影響を受ける調査タスク、調査モニター、評価指標、ロードマップを特定する。

## 出力

- 資料のメタデータと、情報源の由来・継承関係（Source Lineage）。
- 過去FSの項目と現行の調査項目との継承関係を示すマトリクス。
- 新設・変更・廃止候補と根拠。
- `config/research-baseline.json`と人向けカタログの更新案。
- `gap-register.md`の更新。

## 変更条件

- エージェントは既存の調査項目を独断で削除・統合・縮小しない。
- 廃止は`candidate-retirement`として提案し、人が承認した指示（Directive）と、合意判定の結果（Decision）を必要とする。
- 人が具体的に承認した分類・表示・担当範囲の編集は、研究上の結論の変更と分離する。改訂5の再編は`DIR-900014`と`config/catalog-migration.json`に基づく編集であり、研究結果の受理・検証完了を意味しない。AI独自の追加・廃止や科学的判断には従来どおり合意判定を必要とする。
- NDA資料から得た内容は公開リポジトリへ直接持ち込まず、NDA情報の公開用エクスポート手順（NDA Export Protocol）を通す。

## 完了条件

本調査タスクは継続型である。FS2.0とFY2025 FS3.0の正式成果物の登録、および初回の継承マトリクスは完了した。次のマイルストーンは、FS1.0の正式成果物、更新されたFS3.0成果物、センターの一次情報、AIが提案した調査項目を同じ手順で反映することである。
