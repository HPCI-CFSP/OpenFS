# OFS-002: 過去FS資料からの調査ベースライン継承・更新

## 目的

FS1.0、FS2.0、FS3.0および今後のFS成果物から、HPCI整備計画で継続的に調査すべき項目を抽出し、`config/research-baseline.json`を根拠付きで更新する。

## 現在の起点

初期公開版は`docs/research-baseline/source-corpus.md`の4資料から作成した。2026-08-23に文部科学省の令和4〜7年度ページで公開された26資料を登録・レビューし、初期30 Topicを保持したまま27 Topicを追加した。FS1.0、現在のセンター一次情報、評価基準の責任者・重み、および別のFS3提案書の公開区分は未解決である。

## 主な問い

- 過去FSの各調査項目は現在も継承すべきか、内容を改訂すべきか、複数項目へ分割すべきか、または終了条件を満たしたか。
- 過去FSの提言のうち、実装済み、未実装、前提変更、陳腐化、追加検証が必要なものは何か。
- アーキテクチャ、システムソフトウェア、アプリケーション、分野横断課題の間に抜けや重複はないか。
- 各項目を監視する情報源クラス、更新頻度、成果物、評価基準は何か。

## 処理手順

1. 資料の版、公開区分、取得元、SHA-256、原資料との関係を登録する。
2. 章・調査項目・提言を原子化し、既存`topic_id`との対応を作る。
3. 各項目を`inherited`、`revised`、`split`、`merged`、`candidate-retirement`、`new`のいずれかとして提案する。
4. 人またはAIが提案した追加項目について、複数の独立レビューと人のDirectiveを経てベースライン変更PRを作る。
5. 変更後、影響するTask、Monitor、評価指標、ロードマップを特定する。

## 出力

- 資料メタデータとSource Lineage。
- 過去FS項目と現行Topicの継承マトリクス。
- 新設・変更・廃止候補と根拠。
- `config/research-baseline.json`と人間向けカタログの更新案。
- `gap-register.md`の更新。

## 変更条件

- エージェントは既存Topicを独断で削除・統合・縮小しない。
- 廃止は`candidate-retirement`として提案し、人が承認したDirectiveとDecisionを必要とする。
- NDA資料から得た内容は公開リポジトリへ直接持ち込まず、NDA Export Protocolを通す。

## 完了条件

本Taskは継続型である。FS2.0とFY2025 FS3.0の正式成果物登録・初回継承マトリクスは完了した。次のマイルストーンはFS1.0の正式成果物、更新されたFS3.0成果物、センター一次情報、およびAI提案Topicを同じ手順で反映することである。
