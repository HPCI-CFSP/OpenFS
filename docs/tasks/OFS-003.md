# OFS-003: HPCIセンター条件を反映した複数整備案の生成・比較・提示

## 目的

HPCIの大学基盤センター等の現況と更新制約を継続的に把握し、アーキテクチャ、システムソフトウェア、アプリケーションを一体化した複数の実行可能な整備案を生成・比較・提示する。

## 入力

- 受理済みのSource、Claim、Finding、ロードマップ項目。
- `CROSS-08`に基づくセンタープロファイル。
- 技術成熟度、費用、電力、施設、時期、運用、人材、移行、世界技術動向、日本発技術の評価。
- 人のDirectiveで承認された基準、重み、制約、計画対象期間。

## 必須処理

1. 各センターについて、利用者、重点分野、現行資源、更新時期、電力・建屋、ソフトウェア、運用、人材、移行、データ接続を一次情報で更新する。
2. 少なくとも3案を生成し、各案にアーキテクチャ、システムソフトウェア、アプリケーション、センター別影響、世界の技術選択肢、日本発技術の優先調査結果、代替案、不確実性、判断ゲートを含める。
3. 各案を同じ評価軸と時点で比較し、単一のモデルやベンダーの判断を採用理由にしない。
4. 感度分析で順位が変わる条件と、センター別に適合しない条件を明示する。
5. MarkdownとJSONの比較ビューを生成し、報告書草稿から根拠まで追跡可能にする。

## 出力

- 検証済みセンタープロファイル。
- 複数の候補整備シナリオと共通比較表。
- センター別適合性・移行影響表。
- 判断ゲート、未解決点、反対意見、感度分析。
- `reports/drafts/`向けMarkdownと`reports/exports/`向けJSON。

## ガードレール

- 例示シナリオは推奨案でも受理済みFindingでもない。
- 現在情報がないセンターを過去報告書だけで確定評価しない。
- 技術候補は世界から調査・比較し、日本発技術は優先的に探索する。ただし、開発地域だけを理由とする象徴的採用や無条件優先は行わない。
- 高影響な推奨、基準の重み、予算・調達判断は人の承認を必要とする。

## 完了条件

初回マイルストーンは全対象センターの必須項目が一次情報で埋まり、3案以上が同じ評価軸で生成され、独立レビューと人のDirectiveを経て内部提示できることとする。本Task自体は継続型である。
