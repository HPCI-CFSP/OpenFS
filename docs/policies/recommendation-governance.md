# Recommendation Governance

## Separation from factual consensus

An accepted factual Claim does not imply an HPCI recommendation. Recommendation evaluation uses human-owned criteria, constraints, assumptions, and scenario weights.

## Required dimensions

At minimum, evaluate expected scientific value, application coverage, performance, capital and operating cost, power, technology maturity, procurement timing, software readiness, operational complexity, ecosystem risk, resilience, and reversibility.

## Scenario requirements

Roadmaps should present multiple internally consistent scenarios rather than a single unexplained forecast. Each Recommendation records dependencies, decision window, uncertainty, leading indicators, trigger conditions, and alternatives.

## Accountability

Agents may calculate, challenge, and summarize. A named human or governance body owns material changes to HPCI priorities, public commitments, procurement direction, and evaluation weights.
